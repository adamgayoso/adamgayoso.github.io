# adamgayoso.github.io

Source for my personal site. Static HTML generated by a small Python script —
no framework, no lockfile, no `node_modules`.

## Build

Both scripts declare their own dependencies inline ([PEP 723][pep723]), so
[uv][uv] is the only thing you need installed:

```bash
uv run build.py            # build into _build/
uv run build.py --serve    # build, then serve at http://localhost:8000
```

Rebuild in another shell and refresh — the server reads `_build/` directly, so
it needs no restart. Browsers cache `static/css/site.css` aggressively; if a
style change doesn't show up, hard-refresh (Cmd+Shift+R).

## Layout

```
index.md                 homepage: front matter + markdown
posts/*.md               one file per post
posts/_outputs/*.json    cached notebook outputs (committed)
templates/               base.html + one template per page type
static/css/site.css      all the styling
_assets/                 favicons and the og:image
build.py                 the build
execute.py               runs post code cells, writes the output cache
```

Front matter drives everything — `title`, `date`, `summary`, and `draft: true`
to hold a post back. The homepage and `/blog/` listings are generated from it,
so there is no index to maintain by hand.

URLs are directories (`/posts/<slug>/`), matching what the old Sphinx
`dirhtml` build produced.

## Writing

Ordinary markdown, plus three additions:

- **Footnotes become sidenotes.** Write `[^1]` as normal; they are relocated
  into the right margin, and fold back inline below 1000px.
- **Figures** take a width from the image title: `![alt](src "fullwidth")`
  breaks out of the text column, `"marginnote"` puts it in the margin, and any
  other title becomes a caption.
- **Math** is `$inline$` and `$$display$$`, rendered by KaTeX.

## Posts with code

Posts may contain executable cells in [jupytext][jupytext] `md:myst` form:

````markdown
```{code-cell} python
import anndata
```
````

`build.py` never runs them. It reads their outputs from
`posts/_outputs/<slug>.json`, keyed by a hash of each cell's source, and that
file is committed — so the build (and CI) can't break on a missing kernel or a
dataset that only exists on your laptop. After adding or editing a cell:

```bash
uv run execute.py <slug>     # or with no argument for every post
```

A cell whose output isn't cached still renders, just without its output, and
the build prints a warning naming the post. `execute.py` carries its own
dependency block — add whatever a post imports to it.

## Deploying

Pushing to `dev` builds and publishes to the `gh-pages` branch
([`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)).

The workflow deliberately does **not** set a `cname`. `adamgayoso.com` is
forwarded to `adamgayoso.github.io` by the registrar; publishing a `CNAME`
makes Pages claim the custom domain and redirect `github.io` back to the apex,
which the forward bounces straight back — an infinite redirect. For the same
reason `BASE_URL` in `build.py` names `adamgayoso.github.io`, so canonical and
`og:url` point at the host that actually serves the pages.
